SECTION 1: WEB FUNDAMENTALS (Basics)

Q1: What is HTTP and how does it work?

HTTP (HyperText Transfer Protocol) is a request-response protocol. The client (browser) sends a request (GET, POST, PUT, DELETE) to a server, and the server sends back a response with a status code (200 OK, 404 Not Found, 500 Server Error) and data. HTTP is stateless — each request is independent; the server doesn't remember previous requests. This is why we need cookies/tokens for authentication.

Q2: What is the difference between HTTP and HTTPS?

HTTPS adds TLS/SSL encryption on top of HTTP. Data is encrypted in transit so attackers can't read it (man-in-the-middle attacks). In CodeSync, HTTPS is critical because we transmit JWT tokens and user credentials. In production, we'd enforce HTTPS and add HSTS (HTTP Strict Transport Security) headers.

Q3: What is REST API?

REST (Representational State Transfer) is an architectural style for APIs. It uses standard HTTP methods: GET (read), POST (create), PUT (update), DELETE (remove). In CodeSync, our backend exposes REST endpoints:
• POST /api/register — create user
• POST /api/login — authenticate user
• POST /api/logout — clear session
• POST /api/execute/code — run code

Q4: What is JSON?

JavaScript Object Notation — a lightweight data format for exchanging data between client and server. Every API request/response in CodeSync uses JSON. Example: {"username": "mihir", "password": "***"}. Express parses it with app.use(express.json()).

Q5: What is the DOM?

Document Object Model — the browser's tree representation of HTML. JavaScript can manipulate it to update the UI. React creates a Virtual DOM — a lightweight copy. When state changes, React diffs the Virtual DOM against the real DOM and only updates what changed. This is called reconciliation and is why React is fast.

Q6: What are WebSockets? Why can't we just use HTTP for real-time?

Problem with HTTP: HTTP is request-response. The client must ask the server for updates (polling). For real-time code sync, polling every 100ms wastes bandwidth and adds latency.

WebSockets solution: A WebSocket is a persistent, full-duplex (two-way) connection between client and server. Once established via an HTTP upgrade handshake, both sides can send messages at any time without re-establishing connections.

In CodeSync: When User A types code, the change is instantly pushed to User B through the WebSocket — no polling, no delay. 
// HTTP: Client must ask
Client → "Any new code?" → Server → "No"
Client → "Any new code?" → Server → "Yes, here"

// WebSocket: Server pushes instantly
User A types → Server → pushes to User B (instant)

Q7: What is Socket.io and why use it over raw WebSockets?

Socket.io is a library built ON TOP of WebSockets that adds:
1. Auto-reconnection — if network drops, it reconnects automatically
2. Rooms — socket.join(room) groups users; socket.to(room).emit() broadcasts only to that group
3. Fallback — if WebSockets are blocked (corporate firewalls), it falls back to HTTP long-polling
4. Event-based API — socket.emit('event', data) and socket.on('event', callback)
5. Acknowledgements — confirm message delivery

Raw WebSockets give you none of these. You'd have to implement rooms, reconnection, and serialization manually.

Q8: What is CORS and why does it exist?

Cross-Origin Resource Sharing. Browsers block requests from one origin (e.g., localhost:5174) to a different origin (localhost:3000) for security (prevents malicious sites from calling your API).

In CodeSync, our frontend (port 5174) and backend (port 3000) are different origins. We configure Express to allow our frontend: 
app.use(cors({
  origin: ["http://localhost:5173", "http://localhost:5174",
           "https://codesync-mihirkhaitan04s-projects.vercel.app"],
  credentials: true  // allows cookies to be sent
}));

Q10: What is NPM and package.json?

NPM (Node Package Manager) installs JavaScript libraries. package.json lists all dependencies. Key sections:
• dependencies — production packages (react, express, mongoose)
• devDependencies — development only (eslint, vite, tailwindcss)
• scripts — shortcuts like "dev": "vite" (run with npm run dev)

package-lock.json locks exact versions to ensure everyone gets identical installs. node_modules/ contains the actual downloaded code (never commit it — listed in .gitignore).

SECTION 2: REACT FUNDAMENTALS

Q11: What is React and why use it?

React is a JavaScript library for building user interfaces using reusable components. Key benefits:
1. Component-based — UI is split into independent, reusable pieces (CodeEditor, Notepad, Output)
2. Virtual DOM — only updates what changed, not the entire page
3. Declarative — you describe WHAT the UI should look like, React figures out HOW to update it
4. Massive ecosystem — thousands of libraries (Monaco Editor, ReactQuill, React Router)

Q12: What is JSX?

JSX is a syntax extension that lets you write HTML-like code inside JavaScript. It's not valid JavaScript — Vite (via SWC/Babel) transpiles it to React.createElement() calls. Example: 
// JSX (what you write):
<button onClick={handleRun}>Run Code</button>

// Transpiled (what browser sees):
React.createElement('button', {onClick: handleRun}, 'Run Code')

Q13: Explain useState, useEffect, useRef, and useContext.

useState — stores component state. When state changes, component re-renders.
const [language, setLanguage] = useState("c");

useEffect — runs side effects (API calls, socket listeners, subscriptions). The dependency array controls when it re-runs.
useEffect(() => { socket.on("recieve-message", ...); return () => socket.off("recieve-message"); }, [socket]);

useRef — stores a mutable value that persists across renders WITHOUT causing re-renders. Used for: DOM refs (videoRef.current), storing latest values to avoid stale closures.
const editorRef = useRef(null); // access: editorRef.current

useContext — reads values from a React Context (shared state). Avoids prop drilling.
const { user, socket, roomId } = useContext(DataContext);

Q14: What is prop drilling and how does Context solve it?

Prop drilling: passing props through many intermediate components that don't use them.
Example: App → MainPage → AudioVideoScreen → CodeEditor → Output (all need socket)

Context solution: DataProvider wraps the app at the top level. Any component can directly access socket, user, roomId via useContext(DataContext) without passing through parents.

Q15: What is React Router and how do protected routes work?

React Router enables client-side navigation without full page reloads (SPA behavior). 
// App.jsx — Protected routes:
<Route path="/" element={user ? <Homepage /> : <Navigate to="/login" />} />
<Route path="/login" element={!user ? <Login /> : <Navigate to="/" />} />
<Route path="/room" element={user ? <MainPage /> : <Navigate to="/login" />} />
If user is null → redirect to login. If logged in → redirect away from login. This is a ternary-based guard pattern.

Q16: What is the Virtual DOM diffing algorithm?

When state changes, React creates a new Virtual DOM tree and compares it with the previous one (diffing). It uses two heuristics:
1. Elements of different types produce different trees (full rebuild)
2. Elements with stable key props are matched across renders
Then React calculates the minimum set of DOM mutations needed and applies them in a batch. This is called reconciliation.

SECTION 3: NODE.JS & EXPRESS FUNDAMENTALS

Q17: What is Node.js?

Node.js is a JavaScript runtime built on Chrome's V8 engine. It allows JavaScript to run on the server (outside the browser). Key feature: non-blocking, event-driven I/O. It uses a single-threaded event loop that handles thousands of concurrent connections by delegating I/O operations to the OS kernel. This is perfect for CodeSync — WebSocket connections are I/O-bound (waiting for messages), not CPU-bound.

Q18: What is Express.js?

Express is a minimal web framework for Node.js. It provides:
• Routing — app.get('/', handler), router.post('/login', login)
• Middleware — functions that process requests in a pipeline: app.use(cors()), app.use(express.json()), app.use(cookieParser())
• Request/Response — req.body (parsed JSON), res.status(200).json({...})

In CodeSync, Express handles REST API routes (auth + code execution) while Socket.io handles real-time events.

Q19: What is middleware in Express?

Middleware are functions that execute in order for every request. Each has access to (req, res, next). Call next() to pass to the next middleware. 
// Our middleware pipeline:
app.use(express.json());        // 1. Parse JSON body
app.use(express.urlencoded());  // 2. Parse URL-encoded forms
app.use(cookieParser());        // 3. Parse cookies
app.use(cors({...}));           // 4. Handle CORS headers
app.use("/api", auth);          // 5. Auth routes
app.use("/api/execute", execute); // 6. Code execution routes

Q20: What is the Event Loop?

Node.js processes everything on a single thread using an event loop:
1. Execute synchronous code
2. Check if there are pending callbacks (I/O, timers, etc.)
3. Execute ready callbacks
4. Repeat

When a database query runs (User.findOne()), Node doesn't block — it delegates to the OS, continues processing other events, and executes the callback when the query completes. This is why a single Node process can handle thousands of concurrent WebSocket connections in CodeSync.

SECTION 4: AUTHENTICATION & SECURITY

Q21: What is JWT and how does it work?

JWT (JSON Web Token) has 3 parts separated by dots: header.payload.signature
• Header: algorithm (HS256) + type (JWT)
• Payload: data — {id: user._id}
• Signature: HMAC-SHA256(header + payload, JWT_SECRET)

The server signs the token with a secret key. On subsequent requests, the server verifies the signature — if it matches, the token is valid. No database lookup needed (stateless). 
// Login — create token:
const token = jwt.sign({id: user._id}, process.env.JWT_SECRET);
res.cookie("token", token);

// Frontend — persist:
localStorage.setItem("token", data.token);
localStorage.setItem("username", username);

Q22: Why are passwords stored in PLAIN TEXT? Isn't that a security risk?

YES — this is the #1 security vulnerability in the current codebase. Passwords are compared directly: 
if (user.password === password) { // INSECURE! }
If the MongoDB database is breached, all passwords are exposed in cleartext. The fix: 
import bcrypt from 'bcrypt';

// On signup — hash with 12 salt rounds:
const hashed = await bcrypt.hash(password, 12);
const user = new User({...fields, password: hashed});

// On login — compare:
const isMatch = await bcrypt.compare(password, user.password);
if (!isMatch) return res.status(401).send("password incorrect");
Why bcrypt? It's intentionally slow (configurable via salt rounds), making brute-force attacks impractical. Even if the DB is leaked, attackers can't reverse the hashes.

Interview tip: Proactively mention this: "I'm aware this is a security gap — bcrypt hashing would be the first production improvement I'd make."

Q23: What other security improvements would you make?

1. JWT expiry — jwt.sign({id}, secret, {expiresIn: '24h'}) + refresh tokens
2. Rate limiting — express-rate-limit on login/register/execute endpoints
3. Helmet.js — security headers (X-Frame-Options, X-XSS-Protection, CSP)
4. Input validation — validate email format, password length, sanitize code input
5. HTTPS enforcement — TLS in production + HSTS
6. httpOnly cookies — prevent XSS from accessing JWT via JavaScript
7. MongoDB injection prevention — the regex in login (new RegExp("^" + username + "$")) is vulnerable to ReDoS attacks; use escapeRegex() or exact match

SECTION 5: DATABASE (MongoDB)

Q24: What is MongoDB? SQL vs NoSQL?

SQL (PostgreSQL)NoSQL (MongoDB)
Data ModelTables with rows and columnsCollections with JSON documents
SchemaFixed (migrations needed)Flexible (can vary per document)
RelationshipsJOINsEmbedded documents / references
ScalingVertical (bigger server)Horizontal (sharding)
Best forComplex relations, ACID transactionsFlexible schemas, document data, real-time

Q25: Why MongoDB for CodeSync?

1. Data is document-shaped — User = {name, email, username, password} = a JSON document
2. No complex JOINs — we never join Users with Rooms relationally
3. Schema flexibility — can add room metadata, code snapshots without migrations
4. Horizontal scaling via sharding — easier than PostgreSQL partitioning
5. MongoDB Atlas provides a free cloud-hosted tier with auto-scaling

Q26: What is Mongoose?

Mongoose is an ODM (Object-Document Mapper) for MongoDB — it maps JavaScript objects to MongoDB documents. It provides schema validation, type casting, and query building: 
const userSchema = new Schema({
  name:     { type: String, required: true },
  email:    { type: String, required: true, unique: true },
  username: { type: String, required: true, unique: true },
  password: { type: String, required: true },
});
const User = mongoose.model("User", userSchema);
unique: true creates a MongoDB unique index, preventing duplicate emails/usernames at the database level (not just application level).

Q27: What is MongoDB Atlas?

MongoDB Atlas is the cloud-hosted version of MongoDB. Instead of running mongod locally, Atlas manages the database server for you. Benefits: automatic backups, monitoring dashboard, auto-scaling, global clusters. Our connection string: 
mongodb+srv://user:pass@cluster0.ug3pmsb.mongodb.net/codesync
The +srv protocol uses DNS to discover all replica set members automatically.
