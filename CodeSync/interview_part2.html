Project Deep-Dive (Q28-Q60)

SECTION 6: CODESYNC ARCHITECTURE

Q28: Give a 60-second elevator pitch of CodeSync.

"CodeSync is a real-time collaborative IDE and technical interview platform. Two users — interviewer and interviewee — join a shared room to collaboratively write and execute code in 6 languages, take shared rich-text notes, and communicate over peer-to-peer video/audio calls. Built with React+Vite frontend, Node.js+Socket.io backend, PeerJS/WebRTC for P2P streaming, MongoDB Atlas for persistence, and Piston API for sandboxed Docker-based code execution."

Q29: Walk me through the complete user flow.

1. User visits app → React Router redirects to /login
2. Signs up → POST /api/register → saves to MongoDB
3. Logs in → POST /api/login → server returns JWT cookie
4. Frontend stores token in localStorage, updates Context
5. Homepage renders → "Start Interview" or "Join Interview" buttons
6. Interviewer clicks Start → PopupModal generates Room ID (= PeerJS peer ID)
7. Interviewee clicks Join → enters Room ID → navigates to /room
8. AudioVideoScreen mounts: Socket.io joins room, PeerJS establishes WebRTC call
9. Both users see: video feeds, Monaco code editor, ReactQuill notepad, execution panel
10. Any code/note/language change broadcasts via Socket.io to the other user
11. "Run Code" sends POST /api/execute/code → Piston executes → output synced to both users

SECTION 7: FRONTEND DEEP-DIVE

Q31: Why Vite over Create React App?

Vite uses native ES modules in dev → only transforms the changed module (instant HMR). CRA uses Webpack which bundles everything on each save. Vite uses ESBuild for transpilation (100x faster than Babel) and Rollup for production builds with tree-shaking.

Q32: What is the DataProvider pattern?

DataProvider.jsx creates a React Context that wraps the entire app. It initializes: Socket.io connection, PeerJS instance, and auth state from localStorage. Every component can access shared state via useContext(DataContext) without prop drilling. It stores: user, setUser, socket, roomId, setRoomId, status, setStatus, peerInstance, peerId, setPeerId.

Q33: Why Context API and not Redux?

Only ~7 shared values, flat state structure, no complex reducers needed. Redux would add boilerplate (actions, reducers, store, dispatch) for a simple use case. For scaling to many features, I'd consider Zustand or Redux Toolkit.

Q34: What is Monaco Editor?

Monaco is the same editor engine that powers VS Code. It provides syntax highlighting, IntelliSense, bracket matching, and multi-language support. We use @monaco-editor/react wrapper with theme vs-dark, font Fira Code, and minimap disabled.

Q35: How does real-time code synchronization work?

Every keystroke triggers handleEditorChange → emits full editor content via Socket.io: 
socket.emit("message", { room: roomId, data: value });
Other user receives "recieve-message" event → setValue(data) updates their Monaco editor.

For late joiners: on mount, socket.emit("request-code-sync", roomId) → existing user responds with current code, language, and version → new user syncs up.

Q36: Why useRef alongside useState in CodeEditor?

Stale closure problem: Socket event handlers are registered in useEffect. They capture the state value at registration time. If state updates later, the handler still sees the old value.

Fix: useRef always holds the latest value: 
const valueRef = useRef(value);
useEffect(() => { valueRef.current = value; }, [value]);

// In socket handler — always reads latest value:
socket.on("request-code-sync", () => {
  socket.emit("sync-code", { code: valueRef.current }); // always fresh
});

Q37: What is ReactDOM.createPortal?

Renders a component into a different DOM node (e.g., document.body) instead of the parent tree. Used for Focus Mode modals in CodeEditor, Notepad, and Output. Benefits: escapes overflow:hidden and z-index stacking contexts. React events still bubble through the React tree.

Q38: How does the language switching work?

1. User selects language from LanguageDropdown → handleLanguageChange(lang, version)
2. Sets local state + loads boilerplate template from BOILERPLATES object
3. Emits TWO events: "message" (new code) + "change-language" (language setting)
4. Other user receives both events → Monaco re-highlights with new syntax rules

Q39: How does the Notepad sync work?

Uses ReactQuill (Quill.js wrapper). On every content change: 
socket.emit("text-change", { room: roomId, data: newValue });
Other user receives "recieve-text" → setValue(data). Same late-joiner pattern: "request-notes-sync" → existing user responds with current notes.

Q40: What is the requiresInput() function?

Static code analysis that checks if user's code contains input-reading functions before execution:
• C: scanf, getchar, fgets
• C++: cin, getline
• Python: input(
• Java: scanner, system.in
If detected and stdin is empty, a modal prompts the user. Prevents hanging/timeouts on Piston API.

SECTION 8: WEBRTC & VIDEO CALLS

Q41: What is WebRTC?

Web Real-Time Communication — a browser API for direct peer-to-peer audio/video/data streaming. Media flows directly between browsers, NOT through the server. This reduces latency and server costs.

Q42: What is PeerJS?

PeerJS is a wrapper around WebRTC that simplifies the API. Raw WebRTC requires manual SDP offer/answer exchange, ICE candidate handling, and signaling. PeerJS handles all of this with a simple peer.call(peerId, stream) API and provides a free signaling server.

Q43: What are STUN, TURN, and ICE?

STUN (Session Traversal Utilities for NAT) — discovers your public IP/port. Most home networks use NAT, so your private IP isn't reachable from outside. STUN tells you your public address.

TURN (Traversal Using Relays around NAT) — relay server. When direct P2P fails (symmetric NATs, corporate firewalls), TURN routes media through its server as a fallback. More expensive but always works.

ICE (Interactive Connectivity Establishment) — framework that tries multiple connection methods (direct, STUN, TURN) and picks the best one.

In CodeSync, we configure 4 ICE servers (1 STUN + 3 TURN with different transports).

Q44: How does the video call flow work?

1. Interviewer creates room → PeerJS assigns peer ID = Room ID
2. Interviewee joins → gets local camera stream via getUserMedia({video:true, audio:true})
3. Interviewee calls: peerInstance.current.call(roomId, localStream)
4. Interviewer receives: peerInstance.current.on("call", incomingCall) → incomingCall.answer(localStream)
5. Both receive "stream" event → attach to <video> via ref.current.srcObject = remoteStream

Q45: How does video toggle work technically?

Turning OFF: track.stop() (stops camera hardware), removeTrack(), videoSender.replaceTrack(null) (remote sees black).
Turning ON: getUserMedia({video:true}) (re-acquires camera), addTrack(), videoSender.replaceTrack(newTrack) (hot-swaps without renegotiation).

Q46: WebSocket vs WebRTC — when to use which?

WebSocket (Socket.io)WebRTC (PeerJS)
ArchitectureClient ↔ Server ↔ ClientClient ↔ Client (P2P)
Data typeText/JSONMedia streams + DataChannels
Use in CodeSyncCode, notes, language, I/O syncAudio/video calls
ScalabilityRedis Pub/Sub across serversPoor (mesh topology)

SECTION 9: CODE EXECUTION ENGINE

Q47: How does Piston work?

Piston is an open-source code execution engine. Each execution runs in an isolated Docker container with CPU/memory/time limits. The container is destroyed after execution. Supports 50+ languages. API: POST /api/v2/execute with {language, version, files: [{content: code}], stdin}.

Q48: Why Piston and not eval()?

eval() runs code in the Node.js server process — catastrophic: filesystem access, network access, infinite loops crash the server. Piston provides sandboxed, isolated execution. Even malicious code can't escape the container.

Q49: Explain the dual-fallback architecture.

1. Try local Piston (http://localhost:2000) with 5s timeout
2. If fails → fallback to public Piston API (https://emkc.org/api/v2/execute) with 25s timeout
3. This ensures code execution works even without Docker running locally.

SECTION 10: DEVOPS & DOCKER

Q50: What is Docker?

Docker packages applications into containers — lightweight, portable, isolated environments that include everything needed to run (code, runtime, dependencies). Unlike VMs, containers share the host OS kernel, making them faster and smaller.

Q51: Explain the Dockerfile.

# Backend Dockerfile:
FROM node:20          # Base image with Node.js 20
WORKDIR /app          # Set working directory
COPY package*.json ./ # Copy dependency files first (layer caching)
RUN npm install       # Install dependencies (cached if package.json unchanged)
COPY . .              # Copy source code
EXPOSE 3000           # Document the port
CMD ["npm", "start"]  # Start command
Layer caching: Docker caches each step. By copying package.json before source code, dependencies are only reinstalled when package.json changes.

Q52: Explain Docker Compose.

Orchestrates multiple containers as a single application. Our docker-compose.yml defines 3 services:
• piston — code execution engine (privileged mode for nested Docker)
• backend — Node.js server, connects to piston via http://piston:2000
• frontend — Vite dev server

depends_on controls startup order. Docker's internal DNS resolves service names as hostnames.

Q53: What is the Jenkins pipeline?

6 stages: Checkout → Install Dependencies → SonarQube Analysis (static code quality) → OWASP Dependency Check (CVE scanning) → Docker Build + Tag → Docker Push to Docker Hub → Docker Deploy (docker compose up -d).

SECTION 11: SCALING & HARD QUESTIONS

Q54: How would you scale to 10,000 concurrent users?

1. Redis Adapter for Socket.io — enables multiple Node instances behind a load balancer to share Socket.io events via Redis Pub/Sub
2. Nginx reverse proxy with sticky sessions for WebSocket connections
3. MongoDB Atlas sharding for database scaling
4. Horizontal Piston workers for code execution

Q55: What happens when both users type simultaneously?

Current: last-write-wins. Every keystroke sends the full editor content. The last message overwrites. Works for 2-user interviews.

For production: implement CRDTs (Conflict-free Replicated Data Types) using Yjs library with y-monaco binding. Sends only deltas, mathematically guarantees convergence.

Q56: Why not use a VectorDB?

VectorDB (Pinecone, Weaviate) solves semantic similarity search over high-dimensional embeddings — used for AI/RAG/recommendation. CodeSync has no semantic search, no embeddings, no AI similarity. Our data access is key-value lookups and document retrieval, not nearest-neighbor search.

Q57: What is the biggest bottleneck in this architecture?

The single Node.js process. If it crashes, everything dies. Solutions: PM2 cluster mode (multi-process), Docker Swarm/Kubernetes (multi-container), and Redis Adapter for cross-instance Socket.io communication.

Q58: How would you add chat functionality?

Add a new Socket.io event: socket.emit("chat-message", {room, message, username, timestamp}). Store messages in a MongoDB collection for history. On the frontend, add a Chat component that listens to "chat-message" events and renders them. Add pagination for older messages.

Q59: How would you deploy this to production?

Frontend: Vercel (auto-deploys from GitHub push, global CDN, free SSL)
Backend: Railway or Render (supports WebSockets, unlike Vercel for backend)
Database: MongoDB Atlas (already cloud-hosted)
Environment: Set VITE_API_URL to Railway backend URL, update CORS origins

Q60: What would you build next?

1. bcrypt password hashing (security fix)
2. Room persistence — save code snapshots to MongoDB so users can resume
3. Chat system — text messaging alongside video

SECTION 12: RAPID-FIRE (Q61-Q75)

Q61: What does --legacy-peer-deps do?

Ignores strict peerDependency version conflicts. Some packages (react-quill, tldraw) declare outdated peer deps. Without this flag, npm 7+ refuses to install.

Q62: What is ES Modules vs CommonJS?

ES Modules: import/export (used in CodeSync — "type": "module" in package.json). CommonJS: require/module.exports (older Node.js style). ES Modules support tree-shaking and static analysis.

Q63: What is dotenv?

Loads .env file variables into process.env. Called at server start: dotenv.config(). Keeps secrets out of source code.

Q64: What is cookie-parser?

Express middleware that parses Cookie headers and populates req.cookies. We use it to read the JWT token cookie.

Q65: What is SWC?

Speedy Web Compiler — a Rust-based JavaScript/TypeScript compiler. Vite uses @vitejs/plugin-react-swc instead of Babel for 20x faster JSX transpilation.

Q66: What are environment variables in Vite?

Vite exposes only VITE_-prefixed variables from .env to the frontend via import.meta.env.VITE_API_URL. Non-prefixed vars are hidden (security — prevents leaking server secrets to the browser).

Q67: What is TailwindCSS?

Utility-first CSS framework. Instead of writing CSS classes, you compose styles inline: className="bg-slate-900 text-white p-4 rounded-xl". Benefits: no CSS file switching, consistent design tokens, automatic purging of unused classes in production.

Q68: What is the muted attribute on video?

The local video (currentUserVideoRef) has muted attribute to prevent audio feedback loop — hearing your own microphone through your speakers.

Q69: What is scale-x-[-1] on the local video?

Mirrors the video horizontally so it behaves like a mirror (what users expect from a selfie camera). Without it, raising your right hand appears as the left hand.

Q70: What is the difference between emit and broadcast?

socket.emit() sends to the sender only. socket.to(room).emit() sends to everyone in the room EXCEPT the sender. io.to(room).emit() sends to everyone INCLUDING the sender.

Q71: What is Vercel?

Cloud platform optimized for frontend frameworks. Auto-deploys from Git, provides global CDN, free SSL, preview deployments for PRs. Created by the Next.js team.

Q72: What is SonarQube?

Static code analysis tool that detects bugs, code smells, security vulnerabilities, and code duplication. Runs in our Jenkins pipeline to enforce code quality gates.

Q73: What is OWASP Dependency Check?

Scans project dependencies against the National Vulnerability Database (NVD) for known CVEs. Generates a report flagging vulnerable packages.

Q74: What is privileged mode in Docker?

Gives a container full access to the host's kernel capabilities. Piston needs it because it runs Docker containers INSIDE its own container (Docker-in-Docker) to sandbox code execution.

Q75: What is the difference between dev and production builds?

Dev: npm run dev → Vite serves files directly with HMR, source maps, unminified code. Fast but large.
Production: npm run build → Rollup bundles, tree-shakes, minifies, code-splits. Output in dist/ folder. Small and optimized.
